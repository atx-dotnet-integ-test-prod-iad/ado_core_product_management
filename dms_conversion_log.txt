Error Timestamp: 2026-01-22T19:30:12.270515

Root Cause Analysis:
The DMS tool cannot process multi-statement batches that include:
1. Variable declarations (DECLARE @NewProductId INT)
2. SCOPE_IDENTITY() function with variable assignment (SET @NewProductId = SCOPE_IDENTITY())
3. Multiple DML statements referencing the declared variable
4. Final SELECT of the variable value

This is a limitation of the DMS tool's statement parser for complex procedural SQL blocks.

Manual Conversion Applied: YES

Manual Conversion Details:
1. Replaced SCOPE_IDENTITY() with RETURNING clause in INSERT statement
   - PostgreSQL syntax: INSERT ... RETURNING productid;
   - Returns the inserted ID directly from ExecuteScalarAsync()

2. Split into separate statements for ADO.NET execution:
   - Statement 1: INSERT with RETURNING (ExecuteScalarAsync to get new ID)
   - Statement 2: INSERT into ProductHistory using returned ID (ExecuteNonQueryAsync)
   - Statement 3: UPDATE ProductStats (ExecuteNonQueryAsync)

3. Schema name changes:
   - Products -> productmanagement_dbo.products
   - ProductHistory -> productmanagement_dbo.producthistory
   - ProductStats -> productmanagement_dbo.productstats

4. Function replacements:
   - GETDATE() -> CURRENT_TIMESTAMP
   - Column names to lowercase

5. Transaction handling:
   - BEGIN TRANSACTION/COMMIT removed from SQL
   - Will be handled at ADO.NET level using NpgsqlTransaction

Justification for Manual Conversion:
The manual conversion preserves the exact semantic behavior of the original T-SQL:
- Inserts a new product and captures its ID
- Logs the insertion to history with the new ID
- Updates aggregate statistics
- All operations within a transaction for atomicity

The RETURNING clause is the PostgreSQL-standard way to retrieve generated IDs,
equivalent to SCOPE_IDENTITY() in SQL Server.
