Root Cause:
DMS MCP tool cannot process multi-statement transaction blocks with variable declarations 
and SCOPE_IDENTITY() in a single statement. The statement contains:
- BEGIN TRANSACTION/COMMIT
- DECLARE statement with variable
- SET variable from SCOPE_IDENTITY()
- Multiple DML operations (INSERT, UPDATE)
- GETDATE() function calls
- Final SELECT to return the variable

Manual Conversion Applied:
- Removed BEGIN TRANSACTION/COMMIT (will be managed at ADO.NET transaction level)
- Replaced SCOPE_IDENTITY() with PostgreSQL RETURNING clause
- Replaced GETDATE() with CURRENT_TIMESTAMP
- Split into separate commands to be executed within application-managed transaction
- Schema transformations applied manually:
  * Products → productmanagement_dbo.products
  * ProductHistory → productmanagement_dbo.producthistory
  * ProductStats → productmanagement_dbo.productstats

Conversion Method: MANUAL_AFTER_DMS_FAILURE

Reasoning: PostgreSQL handles SCOPE_IDENTITY() differently - the RETURNING clause is the 
preferred method for getting the inserted ID. Transaction management is better handled at 
the application level (ADO.NET) rather than within the SQL statement itself.
