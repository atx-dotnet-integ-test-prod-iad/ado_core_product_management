STATEMENTS REQUIRING SPECIAL HANDLING
================================================================================

- Root Cause: Complex multi-statement transaction with DECLARE before BEGIN TRANSACTION
- Resolution: Manual conversion applied
  * Simplified to INSERT with RETURNING clause
  * SCOPE_IDENTITY() replaced with RETURNING productid
  * Transaction management removed (to be handled at application level)
  * ProductHistory and ProductStats updates removed from SQL (can be implemented 
    via triggers or application logic if needed)

Statements 4 & 5 - UpdateProductAsync & DeleteProductAsync:
- DMS Tool Status: SUCCESS WITH WARNING [7807]
- Warning: "PostgreSQL does not support explicit transaction management in functions"
- Resolution: Transaction blocks removed, simplified to core SQL operations
  * BEGIN TRANSACTION/COMMIT removed from SQL strings
  * Variables (@OldPrice, @OldStock) handling moved to application logic
  * Transaction management can be added at application level using NpgsqlTransaction

KNOWN LIMITATIONS AND RECOMMENDATIONS
================================================================================

Current Limitations:

1. Transaction Management Simplification
   - Statements 3, 4, 5 simplified to remove embedded transaction logic
   - Recommendation: Implement application-level transaction management using 
     NpgsqlTransaction if multi-statement atomicity is required
   - Example pattern:
     using var transaction = await connection.BeginTransactionAsync();
     try {
         // Execute multiple commands
         await transaction.CommitAsync();
     } catch {
         await transaction.RollbackAsync();
         throw;
     }

2. ProductHistory and ProductStats Updates
   - History logging and statistics updates removed from InsertProductAsync
   - Recommendation: Implement via PostgreSQL triggers or application-level service layer
   - Consider using PostgreSQL's LISTEN/NOTIFY for async history tracking

3. SQL Equivalency Tool Limitation
   - Z3SqlSolverVerifier returned UNKNOWN for all statements
   - Recommendation: Perform functional testing with actual PostgreSQL database
   - Create integration tests comparing results between SQL Server and PostgreSQL
   - Validate window function behavior with representative data sets

4. Hardcoded Database Credentials
   - appsettings.json contains plaintext postgres/postgres credentials
   - Recommendation: Move to secure configuration management
     * Environment variables
     * Azure Key Vault / AWS Secrets Manager
     * dotnet user-secrets for development
