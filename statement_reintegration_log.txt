NOTE: The DMS tool converted schema names to 'productmanagement_dbo' which is specific to the DMS migration project schema mapping.
      In production ADO.NET code, we will use unqualified table names and rely on the connection string's database/schema context.
      Transaction management will be handled at the application level using NpgsqlTransaction.

STATEMENT #1: GetAllProductsAsync (Lines 41-71)
BEFORE (MS SQL Server):
  - CTE ProductStats with AVG() OVER() and COUNT() OVER()
  - Table reference: Products
  - No explicit schema

AFTER (PostgreSQL - Adapted):
  - CTE productstats with AVG() OVER() and COUNT() OVER()
  - Table reference: products (lowercase, no schema prefix for ADO.NET)
  - Added NULLS FIRST to ORDER BY clauses
  - All identifiers lowercase

STATUS: Statements remain compatible - CTEs and window functions work in PostgreSQL
ACTION: Column and table names converted to lowercase for PostgreSQL standards

STATUS: Compatible with PostgreSQL

STATEMENT #3: InsertProductAsync (Lines 121-146)
BEFORE (MS SQL Server):
  - Multi-statement transaction with DECLARE @NewProductId
  - BEGIN TRANSACTION / COMMIT
  - SCOPE_IDENTITY() for getting last inserted ID
  - GETDATE() for timestamps

AFTER (PostgreSQL - Application Level):
  - Transaction managed via NpgsqlTransaction in C# code
  - RETURNING productid for getting last inserted ID
  - NOW() or CURRENT_TIMESTAMP for timestamps
  - Column names lowercase

CRITICAL CHANGE: Refactored to use RETURNING clause in INSERT statement
The INSERT will return the new productid directly without needing SCOPE_IDENTITY()
