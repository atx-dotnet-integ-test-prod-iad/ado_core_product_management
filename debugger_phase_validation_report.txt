ISSUE 1: T-SQL Transaction Syntax in InsertProductAsync Method
---------------------------------------------------------------------
Location: DataAccess/ProductRepository.cs, lines 128-164 (before fix)

Problem:
The InsertProductAsync method contained SQL Server-specific T-SQL syntax:
- DECLARE @NewProductId INT (T-SQL variable declaration)
- BEGIN TRANSACTION (embedded in SQL string)
- SET @NewProductId = SCOPE_IDENTITY() (SQL Server identity retrieval)
- COMMIT (embedded in SQL string)
- Multi-statement transaction block in single SQL string

Runtime Impact:
Would result in PostgreSQL syntax errors:
- "syntax error at or near 'DECLARE'"
- "syntax error at or near 'BEGIN'"
- SCOPE_IDENTITY() is not a PostgreSQL function

Resolution Applied:
✅ Refactored to use ADO.NET transaction handling:
   - BeginTransactionAsync() at application level
   - CommitAsync() / RollbackAsync() with try-catch
✅ Replaced SCOPE_IDENTITY() with RETURNING clause:
   - INSERT ... RETURNING ProductId
   - Direct retrieval of generated ID
✅ Separated SQL into 3 distinct commands:
   - INSERT INTO Products with RETURNING
   - INSERT INTO ProductHistory
   - UPDATE ProductStats
✅ Added proper error handling with transaction rollback

Guardrails Verified:
✅ API Compatibility: Method signature unchanged
✅ Test Integrity: No tests modified
✅ Security: No security controls weakened
✅ Code Quality: Improved transaction error handling
